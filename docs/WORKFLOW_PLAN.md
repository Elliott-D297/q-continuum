# Workflow review and plan: OpenFOAM, CalculiX, DEME

**Read this first if you are a Claude session picking this work up.** It records what was asked, what the review found
and the steps proposed, with their state. Nothing here is approved yet: the user approves one step at a time. Update the
progress log at the end whenever a step changes state. Related: `MESH_OVERHAUL_PLAN.md` (meshing, its own steps; overlaps
are marked below), `FEATURE_GAPS.md`, `MESH_AUDIT.md`.

## What was asked (2026-11-14)

"Take a look at the actual workflow of Q-Continuum. What things could be optimized? What things could be made easier for
users who are just learning CFD? Keep the 'hideaway' approach, where things are revealed when you need them, or when you
click an advanced setting. Just create a plan for now that you can access later." Scope, narrowed by the user: **OpenFOAM,
DEME and CalculiX only.** Planning only, no code.

## The hideaway approach, made concrete

One interface, four layers. Every step below says which layer each thing lives in.

| Layer | What is there | How it appears |
|---|---|---|
| 0 | The physical question in fluid-mechanics or engineering words, its value with units, and **one** primary "next" button per page | always |
| 1 | Warnings, explanations, checks, empty-state help | only when they apply: a value out of range, a step not done, a run that failed or finished |
| 2 | Every setting the program has, in the app's own controls | behind an **Advanced** switch or a "More settings" / "Every …" expander; the closed expander shows a count ("3 settings of yours in use") so nothing hidden is forgotten |
| 3 | The raw file | Files page, "All values", "All files": always one click from the control that writes it, never losing work |

Rules: nothing an expert can do today goes away; any setting is at most two clicks from where it matters; the learner never
has to read an OpenFOAM, CalculiX or DEME keyword to finish a first case.

## How the review was done

A throwaway journey (scratchpad only) at 1920x1080, scale 1.5, LCARS and Classic dark, walked:

- **OpenFOAM:** Cases, New case, then a tutorial clone (pitzDaily: Overview, all five Mesh tabs, Boundary conditions, Physics
  tabs, Numerics tabs, Run, Files) and an STL case before meshing (example-duct: Overview, Mesh, BCs, Physics > Setup, Run).
- **CalculiX:** New case, the Cantilever beam starter, Overview, Setup, Run (a real ccx run), Results, Overview after.
- **DEME:** New case, then the user's own `~/deme/settled-bed-heat` opened read-only: Overview, Setup, Run, Results.

The screenshots are not kept. Re-run a walk like this before starting a step, since the app moves on.

## What works well (keep it)

- The STL path's **step strip** (STL → Boundaries → Mesh → Physics → Run, each with a state) on the Mesh and Physics pages,
  and Physics > Setup's "What are you simulating?" cards. This is the best learner spine in the app.
- Overview's **Case check** list, the Run page's **Before you run** box (memory, cores, output size, sensor sweep) and the
  convergence verdict ("Last run converged … all residuals under their targets").
- DEME Setup: physical units, gravity presets, the Rayleigh time-step check, the step count, a time estimate and a particle
  count. DEME Run's "Results from the driver" table.
- CalculiX Setup edits values in place and keeps the rest of the deck byte for byte.

## Findings

### Cross-cutting

1. **Program projects' run button reads as a cut-off sentence.** The header uses the theme's run verb alone
   (`app.c` ~1088, 1277: `term(T_RUN_GO)`), so the Galactic Empire theme shows "Commence primary ignition on", Half-Life
   "Push the sample into", Stardew "Get to work on" and Pokémon "Go,". The Run page adds the input name; the header doesn't.
   The Empire wording came from the 2026-11-14 theme work.
2. The header carries 7 actions on every page (Clean, Undo, Redo, Saved, ParaView + Claude, ParaView, Run). Clean is a
   destructive action and sits next to Undo.
3. Toasts stack three high in the bottom right and cover buttons there (seen over CalculiX Setup's fields).

### OpenFOAM

4. **Two different apps depending on how the case was made.** Physics > Setup (the guided path, Numerics presets,
   BCs written from roles) appears only when `simulation.ini` / `mesher/mesher.ini` exists or the case has no physics
   files (`page_dicts.c` ~485). Every "Good places to start" tutorial, imported case or opened folder gets the raw
   dictionary pages instead. The New case page sends learners there first.
5. **The step strip exists only for STL cases.** Tutorial and blockMesh cases have no "where am I, what's next".
6. **Dead ends and wrong hints before Physics is written** (STL case):
   - Boundary conditions says only "No field files were found in the initial-conditions folder".
   - Overview's "No initial conditions" item has no button to the fix (Physics > Setup > Write case files).
   - Overview's Patches card lists blockMesh's `background` patch for a snappy case.
7. **Mesh page:**
   - Five tabs of equal weight (Dictionaries, STL mesher, SALOME script, View, Quality), whatever made the mesh.
   - The subtitle under the title stays "blockMesh builds this mesh from system/blockMeshDict…" on the View and Quality tabs.
8. **Boundary conditions in raw types only:** `epsilonWallFunction`, `calculated`, `kqRWallFunction`, `nutkWallFunction`,
   four fields to a screen ("Fields 1-4 of 7"). A learner thinks "inlet at 10 m/s, walls no-slip, outlet open".
9. **Settings with two homes:**
   - The Run page edits solver, end time, time step and write interval, which Physics > Setup also sets.
   - Numerics presets (Robust / Balanced / Accurate) live in Setup; the Numerics page shows raw schemes only.
10. **No results step.** The workflow ends at Run with the residuals; the answer (forces, pressure drop, mass balance,
    outlet temperature, y+) is in ParaView or on the Run page for some templates. There is nothing that says "here is your
    answer, and here is how far to trust it".
11. "Good places to start" cards say what the case is, not what it teaches or what answer to expect.

### CalculiX

12. **Setup shows deck cards, not engineering:** `boundary = FIXED, 1, 3` and `load = TIP, 3, -40.`. A learner needs "fixed
    support on node set FIXED, x, y and z held" and "40 N downward on TIP". Material is three bare numbers.
13. **No units check.** CalculiX has no units; the page labels E as "Pa (SI model)". A deck in mm-N-MPa with E = 210000 is
    common and nothing would catch the mix.
14. **Run page shows a CFD layout for a linear static step:** an empty residual chart ("Residuals appear here while a solver
    runs"), steps 0, simulated time "-", wall time 0 s.
15. **Results is a file list** (.cvg, .dat, .frd, .sta with Read / cgx). No maximum displacement or stress, no reaction
    check, no picture of the deformed part, no comparison with the hand calculation the starter invites (δ = PL³/3EI).
16. No view of the geometry or mesh in the app before running; only two starters.

### DEME

17. **Particle viewer shows "No particles in this frame"** on Overview and Results for a 31-frame run (the newest frame is
    empty).
18. **Results chart defaults** plot `t_phys` against `t_sim` (time against time), which dwarfs the temperatures.
19. **Run status "Last run stopped"** at t = 1.5 of 1.5 s with the driver's final results printed. Possibly a finished run
    labelled as stopped (`app.c` ~1598 marks external runs stopped when the summary isn't CS_DONE). Check before fixing.
20. **Setup mixes physical and numerical parameters at one level:**
    - Numerical tricks sit next to grain density with no word on what they change: "Real Young's modulus" against the
      stiffness used, "Thermal speed-up 2e6", "Profile layers", "Size bins".
21. The Run page always shows "Rebuild before running" and "Run with an OpenFOAM case" (coupling). Both are expert or
    occasional.
22. Driver results (k_eff_estimate, solid_fraction, T_mean_end) come without context. Is 0.504 a sensible solid fraction?
    How does k_eff compare with a packed-bed correlation?

### Speed (optimization)

- Frame times are fine (p95 1-3 ms in the walk). The speed to win is the user's, in clicks and in waiting:
  - Re-running a whole snappy mesh for a layer change (in the mesh plan, step 9).
  - DEME rebuilds decided by a checkbox rather than by whether the sources changed.
  - CalculiX defaulting to 4 OpenMP threads on a 32-core machine.
  - No "next" button, so the learner hunts through the sidebar.

W0 (cheap, removes confusion) → W1 → W2 (largest learner gain: the tutorials learners start from get the guided path) →
W3 → W5 → C1 → C2 → D1 → D2, then W4, W6, W7, W8, C3, C4, D3. X1 should land before W5 if the mesh plan hasn't done it.

### How each step is verified

As in the mesh plan:
- Journeys in the sandbox for every new path.
- Screenshots looked at, at 1440x900 scale 1.0 and 1920x1080 scale 1.5.
- A learner walk-through per program, with no keyword needed to finish the starter:
  - OpenFOAM: "water through a pipe at 2 m/s" to a result.
  - CalculiX: the beam to its deflection, checked against PL³/3EI.
  - DEME: "settle a bed of glass beads" to a solid fraction.
- Hand-worked examples in `docs/` for every comparison with theory (C2, D2).
